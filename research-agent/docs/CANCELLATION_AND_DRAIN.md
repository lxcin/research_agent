# 取消与插件后台任务排空

## Docker 命令

带取消令牌的前台任务复用所属沙箱会话，后台任务使用独立命名容器。取消或超时时先 rm -f 所属容器，确认成功后才按停止处理；不会仅终止宿主 docker 客户端而声称容器已停止。前台取消会销毁整个会话容器，容器内临时状态不保留。

无法确认删除时，记录工作区 quarantine 标记，后续合作请求与回滚拒绝进入；管理员必须核对容器已停止后再移除标记。它是失败关闭策略，可能在容器尚未创建/已自行退出时产生保守隔离。标记保存在 data_dir/quarantine。仍不防止外部编辑器操作。

2026-10-15 补齐普通会话关闭：SandboxSession.close 检查 docker rm 返回码，超时或连接异常保留容器标识，不设置 closed；明确报告对应容器不存在时允许幂等清理。end_run 在确认关闭后才清空 State 引用；失败会使顶层任务进入 recovery_required。close_all_sessions 重试进程内失败资源；已移除跨轮持久会话。容器创建前记录持久化意图并添加安装/槽位标签，崩溃后凭空闲槽位 OS 锁核对回收，不只依赖内存表，详见 [Docker 归属与验收](DOCKER_OWNERSHIP_AND_ACCEPTANCE.md)。

## 后台命令与会话关闭

后台任务由宿主 BackgroundTasks 服务管理，任务记录和取消请求进入 SQLite WAL。回复结束后仍可通过执行编号或任务编号取消。关闭会话先持久化拒绝接入标记，再取消并等待请求及任务归还凭证；停用 Shell 插件和退出应用也先取消再排空。超时返回未完成，未知结果进入 recovery_required，不把线程退出或取消请求当成容器清理成功。查询/取消控制入口不需要工作区写入锁，见 [后台任务生命周期](BACKGROUND_TASKS.md)。

## 阻塞模型调用

运行侧用可取消等待包装模型原语，传输线程保留请求凭证，取消后不接受迟到结果；本地线程真正退出才释放工作区。LiteLLM 默认注入 60 秒超时、关闭隐式重试，显式配置可覆盖。流式消费无论成功或异常都会关闭支持 close 的响应对象。

不强杀 Python 线程，不承诺供应商停止计算/计费。底层忽略超时时凭证仍持有，不会假装已安全停止。自定义适配器仍须遵守超时/资源关闭契约。

## 计划插件停用

ResourceScope.on_drain 在资源清理前关闭任务入口。计划插件绑定 plan_pipeline.pause：禁止领取新任务，等待 active 归零后才继续卸载。已提交未领取任务保留 SQLite pending；重新启用打开入口，后续宿主 recover_pending 重新领取。内存队列条目可以丢弃，数据库记录不删除。任务模型调用结束前不提前释放提炼资源。

当前提炼工作线程是应用级常驻调度器，停用暂停其业务处理，不销毁线程；多独立应用实例应使用独立进程/数据目录，不能在同一进程用多个注册表管理同一全局 pipeline。

## 验证

线程异常警告按错误处理。覆盖计划提炼排空、暂停恢复、阻塞模型取消后的凭证保护、Docker 清理失败、后台跨进程取消、关闭单一会话及重新打开、应用/插件退出和审批登记竞态。真实 Docker daemon 七项验收已通过，包含后台命令在回复后取消并释放工作区。最新验收记录见 [后台任务生命周期](BACKGROUND_TASKS.md)。剩余边界包括供应商远端取消保证、原生异步客户端关闭及未知结果的人工核对/隔离管理界面。
