# 三个闭环的验收与边界

## 验收记录（2026-10-15）

结论：已实现路径有条件通过；不是整个应用架构的无条件验收。全量 pytest：415 passed、1 skipped，8 条第三方依赖弃用警告。

| 闭环 | 验证场景 | 结果 |
| --- | --- | --- |
| 排空释放 | 活跃调用阻止释放、新调用拒绝、窗口隔离、超时后继续等待、清理失败只重试失败项、异步清理完成 | 通过 |
| 证据 | 无收集器时积压、独立进程归档、重复归档去重、缺序号拒绝完整性、重复关闭不破坏闭合轨迹 | 通过 |
| State | 版本迁移、恢复校验失败不部分更新、保存序列化失败保留原文件、卸载再保存后仍可恢复数据 | 通过 |

验收修复：关闭成功后再次 close 不再追加 drain 事件；save 合并未加载字段快照，避免卸载插件后后续保存误删其数据。

验收未覆盖：收集器在事务提交瞬间被杀的故障注入、断电持久性、长时间压力、事件循环绑定资源、同会话并发写冲突、模型/诊断资源全量迁移。独立进程验证使用 --once，不等同于长期收集器运维验收。快照合并仍不提供跨进程并发更新保护。

## 执行、排空、释放

ResourceScope 的注册与调用入口受 Condition 保护；停用先关闭入口，已有凭证退出后清理。PluginManager 控制面变更由可重入锁串行化。同步工具及后台 Shell 已持有执行凭证；aclose 将等待与清理放入工作线程，own_async 支持独立事件循环执行的异步清理。绑定特定事件循环的资源不能使用该桥接，仍需宿主原生异步生命周期。当前不得在自身持有凭证的调用里同步卸载自身。

## 事件、落盘、重放

UDP 已替换为 SQLite WAL 持久化 outbox。生产者进行短同步提交；独立 collector 在同一事务内归档到 evidence 并移除 outbox，主键去重，收集器离线不会丢掉已提交事件。无法在“任意崩溃不丢失”前提下同时保证“完全无同步持久化成本”。outbox 提交失败记录明确异常日志，不阻断资源释放；后续序号缺口不会被当作完整证据。

运行 python -m research_agent.evidence --database DATA_DIR/evidence/lifecycle.db；--once 支持归档积压后退出。端口参数仅保留兼容，不再使用网络。read 返回 pending、incomplete、complete，统一评测显式显示未归档/未闭合证据；运行中和崩溃残留目前同属 incomplete，尚无心跳区分。数据库连接退出时显式关闭，避免 Windows 文件占用。

## 字段、恢复、保存、卸载

StateComponent 可声明 validate、version、encode/decode 和 migrate。factory 与 set 经校验，restore 先暂存全部值并校验/迁移，通过后更新容器；save 使用同目录临时文件、fsync 和原子替换。仅显式提供 encode 的字段持久化。宿主按工作区+会话身份恢复和保存声明字段；卸载清理运行实例，不隐式删除快照。未知/已卸载字段不会恢复到 State。

默认兼容字段未自动添加持久化，既有会话存储继续使用原路径。原地修改可变值仍会绕过 set 校验；多窗口同时写同一个会话尚无乐观版本冲突控制。插件需保证迁移纯净和清理幂等，恢复替换需要外部资源的字段应使用专门的资源恢复协议，不能直接将活动连接序列化。

验收覆盖独立进程重放、重复归档、字段版本迁移与卸载、异步清理，以及既有生产工具排空/窗口隔离测试。以上是已覆盖路径，不代表所有模型、诊断横切资源和异步流均已迁移。
