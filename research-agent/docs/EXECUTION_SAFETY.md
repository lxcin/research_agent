# 执行可靠性处理记录

当前网络恢复契约（2026-10-15）见[网络中断与执行恢复](NETWORK_RECOVERY.md)：默认内核保存步骤阶段，宿主有限自动重试并复用完成结果；未变化的恢复沿用原 S，真正完成才封存 E。下文保留各阶段历史验收记录，不应把旧的“尚无循环检查点”等描述理解为当前状态。

## P0 取消与恢复接口补齐

HTTP ChatRequest 接收可选 execution_id，SSE 先返回 execution 事件。POST /api/executions/{execution_id}/cancel 定向设置令牌并唤醒审批；不再用 chat id 覆盖不同活跃执行，退出时移除活跃条目。接口只表示已请求协作取消，不承诺所有外部操作已停止。

执行日志与循环检查点过滤不可 JSON 编码的运行资源；重放合并可恢复 caps，不覆盖当前沙箱实例。非序列化插件数据不会自动恢复，插件应另行声明恢复协议。补充测试证明活动资源不再导致 ToolResult 落库失败。

回合后压缩进入 execute_once，完成后不重复调用，结果不确定则要求核对。情景记忆按 execution_id 派生稳定 id，重复提交覆盖同一条情景，不产生多条记录。但内存异步队列仍可能在进程退出时丢任务，稳定 id 只解决重复落库，不等于持久任务调度；提炼可能重复消耗模型费用。语义自评等其他旁路也尚未全部去重。

本轮全量 434 passed / 1 skipped，读取线程警告按错误处理，仅余 8 条依赖弃用警告。新增验证包括定向取消不影响其他执行、唤醒审批、活跃资源与持久化状态分离。

仍需推进：Docker 与阻塞模型调用取消、持久异步提炼队列、外部副作用核对/补偿界面、原生异步资源绑定、回滚极短竞争窗口。P0 尚未全部关闭。

## P0 后续验收

读取线程警告已复现：测试全局 patch threading.Event.wait 破坏 subprocess 在 Windows 上的读取线程启动/等待，导致 I/O operation on closed file。修复为仅 patch 审批等待接缝 _wait_for_approval；全量将 PytestUnhandledThreadExceptionWarning 提升为错误后 425 passed / 1 skipped，仅余 8 条依赖弃用警告。

process_control.run_local 轮询取消/超时并终止本机进程树，输出写临时文件，避免管道读取线程问题。生产前台/后台本机 Shell 接入；Docker 和阻塞供应商调用不具备同等停止保证。后台元数据记录 cancelled，线程最终释放凭证。

请求文件锁改为引用计数凭证。后台任务在启动前 retain，请求退出不提前解锁；后台真正结束才释放最后一个引用。进程退出仍由操作系统释放。会话保存使用 execution_id 去重；情景提炼和压缩等其他回合后副作用未全面幂等。

ProposalManager 对已 collect 的文件记录内容摘要，keep/undo 检测审阅后变化，批量操作不重新覆盖原审阅基线。仅同一个管理器内有效，不覆盖用户在检测与操作间的竞争、HEAD 基线变化或新管理器重建；Git checkpoint 整体恢复也尚无同等保护。因此用户编辑与回滚冲突仍未彻底解决。

专项覆盖真实本机睡眠进程取消、请求结束后后台凭证继续阻止写入、同一执行重复保存只产生一轮、审阅后用户编辑被保护。

## 本轮 P0 更新

默认内核在执行工具前保存消息、待执行调用及调用 id；每个工具回灌后保存轮数、失败数和 caps。相同 execution_id 与请求/工作区/会话/kernel id 可恢复待执行队列，已完成工具由执行记录复用，不再依赖模型重新生成相同 id。请求身份不一致或工具状态不确定返回 recovery_required，终止整个循环。ToolResult 与兼容 caps 同时保存；任意插件对象和非 caps 临时字段尚未完整恢复。

恢复入口：调用 run_agent(..., execution_id="调用方稳定保存的任务标识")。这不是自动恢复 API；调用方必须保存该标识并明确触发恢复。自定义 Kernel 需自行使用宿主 checkpoint，默认实现已接入。检查点原文包含上下文和工具数据，需要按用户数据保护，尚无加密/保留期限。

State 保存增加操作系统锁与已加载文件摘要比较；旧版本保存明确拒绝，避免覆盖新快照。子代理共享父取消令牌，工具调用使用父调用/子代理命名空间，避免执行日志 id 冲突；流式片段和模型重试入口也检查取消。运行中的阻塞供应商请求、子进程以及后台任务仍需专门停止协议。

验证：全量 421 passed / 1 skipped；最后结果封装调整后专项 12 passed。专项出现子进程 readerthread 警告，尚未定位，不把它归为正常弃用警告。恢复故障注入验证“结果已落库、循环检查点未推进”不会重复执行工具；State 验证旧写入者被拒绝。

剩余 P0：用户编辑与 Git 回滚冲突保护、后台任务持续工作区占用、原生子进程取消、跨进程子代理检查点、外部副作用人工核对/补偿、回合后保存幂等。当前不能承诺任意崩溃位置均能无重复地恢复；尤其最终回答已生成后重新进入外壳可能重复回合后处理。

## 已接入生产路径

run_agent 在进入生命周期前取得工作区和会话的操作系统文件锁，冲突立即报错，退出自动释放；进程退出由 OS 释放。不同工作区与会话仍可并发。该保护覆盖本服务的请求，不阻止用户编辑器写文件，不保护此前已启动并脱离请求的后台任务，也不保护独立 CLI 提案/回滚操作。

每回合设置 execution_id，默认新 UUID，可由调用方显式传入。ToolRegistry 按 execution_id + tool_call_id 记录 signature、started、completed 和完整 ToolResult。完成记录可复用；参数不一致拒绝；started 未完成拒绝自动重放，要求先核对外部状态。它防止已知调用身份的重复执行，不提供任意外部系统的 exactly-once，也不能仅靠重新传 execution_id 恢复原模型消息与工具调用 id。

CancellationToken 经 State 私有兼容字段传递，RuntimeHost 在模型、工具与回答入口检查；Cancelled 不被普通重试捕获。run_agent 返回 cancelled 终止原因，已发生副作用不会回滚。同步供应商调用、运行中子进程、远程请求和后台线程尚不能被强制中断；必须继续补工具级协作取消、超时与子代理传播。
