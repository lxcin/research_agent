# 情景提炼任务的持久化恢复

提交时先将 digest、工作区、会话及是否使用模型写入 episode_jobs.db，再唤醒内存工作线程。内存队列只是唤醒机制，SQLite 才是任务事实源。状态为 pending/running/completed/failed，错误文本保留在 failed 行。

工作者以操作系统锁互斥领取同一任务。进程退出释放锁，下一次恢复可重领 running。重复唤醒 completed 不再执行；failed 默认不重试，recover_pending(llm=..., retry_failed=True) 显式重试。生产请求在 plan 插件开启时调用 recover_pending，恢复未完成任务；没有新请求时需宿主显式调用恢复入口。

模型客户端、凭据不序列化。提供当前 llm 时可继续模型提炼；显式不提供时使用启发式回退。情景记录 id 由执行 id 派生，落库后未标记 completed 时崩溃，再运行只更新同一记录。模型调用可能重复产生费用，这是至少一次处理，不是外部 exactly-once。

相同任务 id 不允许提交不同内容，避免覆盖原始任务。save_plan 失败会令队列进入 failed，不再被当作成功。drain(timeout) 真正执行超时，避免测试或关闭流程无限等待。

验收：独立进程领取后 os._exit，父进程重新领取并完成；已完成任务重复处理无副作用；失败默认不重试、显式重试成功；无模型客户端恢复产生情景记录。
