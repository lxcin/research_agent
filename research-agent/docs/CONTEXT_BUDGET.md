## 预算实现收尾

现已使用 BudgetReport 记录窗口、输出预留、安全余量、裁剪前后输入估算、移除块数和计数来源。每次选择/回答都会检查 input_after + output_reserve + safety_margin <= window；拒绝请求发出 rejected 事件及原因。完整工具协议在裁剪前校验，拒绝孤立结果、重复结果与未完成工具组。

context 配置支持 window_tokens（显式模型窗口）、output_tokens、safety_tokens、image_tokens、tool_result_tokens。缺少窗口配置时仍使用既有模型名称映射，它只是默认值，不是实时规格。输出预留通过请求局部 ContextVar 传入实际 LiteLLM 工具/流式调用的 max_tokens，不再只记账不限制输出。自定义调用原语须遵守同一输出上限契约。

RuntimeContext.token_counter 可注入适配器计数函数。默认使用 cl100k 文本估算、消息额外开销及每张图片的配置预留，不将 base64 图片按文本计费；不支持的多模态类型会拒绝并要求提供计数器。它不是所有供应商的精确计数保证。模型返回 prompt_tokens 时记录 context_calibration，估算不足会增加本次运行后续请求的保守开销，不跨会话学习。

大结果阈值可配置并随窗口缩放，外置产物改为 fsync + 原子替换。产物读取不再次外置，避免引用递归。保留关键错误、成功标志和返回码。

验证：全量 450 passed / 1 skipped；最后校准与原子产物调整后关联专项 31 passed，新增实际用量校准测试后预算专项 7 passed。覆盖实际 max_tokens 与预留一致、图片 payload 长度不污染估算、整组裁剪、工具协议拒绝、必需输入超限、适配器用量反馈。

完成的是预算执行闭环。真实供应商 tokenizer 校准、音视频计数、摘要约束保真与真实任务消融仍未完成；不会将估算器称为精确供应商计数器。

RuntimeHost 在每次模型选择和最终回答前计算请求预算，包含序列化消息、工具 schema 和输出预留。旧 trim_messages 不再原地截断字符串。预算不足时先移除历史对话/摘要块，再按完整 assistant/tool 调用组移除旧工具交互；当前输入、其他系统指令、显式约束及最后一组工具交互保留。必需信息仍超限则 context_limit 退出，不付费重试同一超限请求。

工具结果超过阈值后保存在 data_dir/context_artifacts，模型获得预览、artifact_id、原始长度与分段读取指引，基本错误/状态信息保留。context_result_read 属于 filesystem 插件，只能访问当前工作区+会话命名空间，限制 id 格式和读取长度。读取产物本身不再次外置，避免嵌套引用；完整工具原语返回数据仍在日志/检查点各自协议下保存。

constraints 是独立注入的可持久字段，每次模型调用重新加入，不依赖摘要。当前由调用方显式提供，尚无约束自动抽取、变更确认与摘要保真评测。旧摘要与对话块可整个移除，因此不能声称自动保留了未显式登记的历史约束。

预算是 cl100k_base 的保守文本估算，不是供应商精确 tokenizer 或多模态费用估计。工具结果外置需要 filesystem/context_result_read 可用；自定义注册表没提供读取工具时保持原结果，超限会停止。初始历史采用整块移除，不是高质量语义压缩。产物尚未实现保留期限、访问审计及跨会话授权。

第一阶段验证：全量 446 passed / 1 skipped。覆盖完整结果分段可还原、跨会话不可读取、历史删除不修改原消息、显式约束保留以及超大当前输入明确失败。后续：摘要保真与原文回溯、跨模型预算校准、产物容量管理，以及真实任务上下文消融评测。
