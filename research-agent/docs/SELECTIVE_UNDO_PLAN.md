# 三方合并与选择性撤销设计及实现

更新：2026-10-15。按轮快照、最近一轮选择性撤销及三方文本合并已实现。本文区分当前契约、验收范围与后续设计，不承诺任意历史撤销。

基线简化已实施，见[基线与恢复修改计划](WORKSPACE_BASELINE_AND_RECOVERY_PLAN.md)：正常新轮从实际工作区建立基线，三方合并只在主动撤销时使用；旧 E 缺失不再阻断安全的新轮。

## 目标与现状

目标是撤销指定一轮、指定文件的变化，同时保留执行前已有的人工修改，以及执行结束后不冲突的人工修改。整轮快照恢复继续保留为独立能力，不自动切换为合并。

当前 checkpoint 保存执行前和结束后的原始文件内容、权限、HEAD 和真实 index。文件内容存入共享 Git 对象库，index 对应的树另有可达引用，避免原有暂存对象被回收。proposal 展示本轮 S→E 差异，不再把执行前人工内容与 HEAD 的差异当作本轮 Agent 输出。

保留单位是一次用户请求对应的一轮 Agent 执行，不是一次工具调用或整个聊天窗口。默认 turn；旧 command 配置兼容为 turn，不再按工具调用积累快照。下一轮先从**实际工作区**建立新 S，包含两轮间人工修改；成功发布后释放上一轮 S/E、候选结果和备份引用，以及对应完整快照元数据。没有自动 Git 提交，也没有提前执行三方合并。只有撤销时才需要合并。

正在应用/部分失败的撤销、仍在执行或结果未知的后台任务、工作区隔离继续阻止新轮。仅缺旧 E 不阻断；未应用的冲突计划在新 S 成功后自动过期，旧令牌失效，冲突目录独立保留供人工处理，后续换轮也不自动删除。新 S 失败则保留旧引用、计划与产物。关闭快照会停用旧轮提案关联，但不在没有新备份时清除其恢复引用；重新启用并成功开始新轮后再清理。非 Git 工作区不提供快照撤销。

后台任务排空后自动通过[持久化完成消息](BACKGROUND_TASKS.md)补齐 E：最后一个写入凭证释放前固定原始结束版本，再消费 snapshot_ready 发布不可变基线。延迟重放不吸收后续人工编辑；没有可信 ready 的捕获中断标为 undo_unavailable，不猜测旧 E；没有残留写入时允许建立新 S。

Git 相同内容共享对象；C 不会在每次预览时整库复制。候选结果仅保存需要写入的内容；真正应用前才保存完整备份。正常保留最近一轮，换轮时短暂重叠；中断恢复所需数据是例外。释放引用后提交持久化异步维护任务，由独立进程执行保留宽限期的普通 GC，不阻塞对话；详见[Git 后台回收](STORAGE_POLICY.md)。释放引用不等于立即释放磁盘，也没有磁盘硬配额。

第一版支持最新一个已封存执行的按文件撤销。任意历史轮次、按 hunk 撤销、撤销提交历史、自动解决语义冲突不在第一版范围。执行前后 HEAD 不同则拒绝自动撤销，交由提交历史处理流程；不移动分支。

## 三个版本与撤销方向

| 记号 | 内容 | 用途 |
| --- | --- | --- |
| S | 执行前工作区快照，包含当时人工未提交内容 | 撤销目标侧 |
| E | Agent 结束且后台已排空时封存的完整快照 | 反向合并的共同祖先 |
| C | 本次审阅时的当前工作区 | 保留的当前侧 |

正向增量是 S → E，撤销增量是 E → S。目标结果 R = merge(base=E, ours=C, theirs=S)。**反向合并的 base 是 E，不是 S**；S 是任务历史上的执行前基线。这是同一套撤销机制的两个环节：先确定应撤销的增量，再用三方合并保留后续编辑。

例如 S 中已有人工修改 A；Agent 在另一处增加 B 得到 E；人工随后增加 C。撤销结果应保留 A 和 C，移除 B。若人工随后修改 B 所在代码，必须报告冲突，不猜测哪些语义可以删除。

这里的“Agent 补丁”实际指受控执行区间 S → E 的变化。独立 worktree 能隔离其他会话，不能阻止编辑器在同一次执行期间写入。若期间发生人工混写，仅靠两张快照无法区分作者；需要工具写入记录等证据辅助提示，且 Shell 记录仍非完整作者证明。执行期已知外部混写应阻止自动撤销，无法保证归因时需明确披露并由人工逐项审阅，不能宣传为严格作者级撤销。

## 责任与拟定契约

内核不参与。runtime 负责开始/结束边界及排空；checkpoint 负责不可变快照；撤销规划器只根据版本生成候选结果；宿主负责审阅、锁、备份、应用、恢复与审计；proposal 和 CLI/API 使用同一套服务。

独立 rollback 模块负责规划、审阅、冲突和应用入口；checkpoint 的宿主内部执行器同时承载严格恢复与选择性撤销，复用备份、逐文件写入、index.lock 和恢复日志。公开入口不能传入任意 prepared 计划绕过审阅。

| 当前契约 | 责任 |
| --- | --- |
| 快照 version=2 / active-turn | S/E 内容引用、原始字节摘要、权限、开始/结束 index、HEAD；按物理 worktree 隔离，关联 execution_id/chat_id |
| UndoRequest（冻结 dataclass） | 本轮引用、明确的文件集合、显式解决的冲突路径；不接收任意写入目标 |
| selective-undo version=1（持久化计划） | plan_id、S/E/C 身份、选择范围、逐文件操作和结果摘要、候选 Git 引用、预览及截断说明 |
| review_undo(workspace, ref, paths, resolved=...) | 生成并保存候选计划/冲突产物和审阅令牌，不修改业务文件或 index |
| apply_undo(workspace, review_token=...) | 重新校验、备份、持久化日志、应用与结果验证；应用时不重算或批准新合并结果 |
| cancel_conflict(workspace, review_token=...) | 仅放弃尚未开始应用的冲突计划，不丢弃业务文件，不用于取消部分恢复 |

请求使用 dataclass，持久化记录使用带 version 的 JSON 契约，目前没有把所有内部字典都改为静态类型对象。冲突是显式结果，不通过空 diff 冒充成功。审阅令牌不是身份认证凭证。

## 文件与暂存区策略

按 S/E 差异确定作用域；S=E 的文件，即使 C 有变化也保持不动。第一版的语义如下。

| 文件情况 | 处理 |
| --- | --- |
| 普通文本，C=E | 直接恢复 S |
| 普通文本，C≠E | 以 E 为祖先合并 C 和 S；无冲突才生成候选结果 |
| Agent 新增，S 不存在 | C=E 才删除；C 已修改则冲突，即使删除部分内容似乎可行 |
| Agent 删除，E 不存在 | C 仍不存在则恢复 S；人工已重建该路径则冲突 |
| 二进制 | C=E 时允许审阅后的精确恢复；有后续变化则冲突，不做合并 |
| 重命名 | 按删除旧路径、增加新路径分别处理；需要完整撤销时显式选择两者，不推断文件身份 |
| 权限改变、文件/目录类型改变 | 无后续变化时精确操作；歧义、目录占用或涉及未知数据时拒绝 |
| 链接、submodule、路径逃逸、忽略文件占位 | 拒绝自动处理，不跟随链接、不覆盖未知资源 |

文本合并先支持可严格解码且可保持换行/编码的有限集合；记录 BOM、CRLF/LF、无末尾换行等信息。不能无损还原时拒绝，不以替换字符解码后写回。Git tree 的 clean/smudge 可能改变字节：快照必须能重建原始字节，现有“过滤后哈希不符则拒绝”边界保持，不能假设 Git blob 等于工作区原始字节。

**index 作为独立状态处理，不能用工作区合并结果覆盖人工暂存。** 第一版采用严格策略：

1. 当前整个 index 必须与封存 E 的 index 一致；结束后任何人工暂存变化均拒绝，先不做 index 三方合并。
2. 对选中文件恢复 S 中的 index 条目，保留未选中文件在 E 中的 index 条目；不能按文件撤销却恢复整个开始 index。
3. 在临时 index 中构建结果，校验条目、对象及预计差异；支持范围先限定普通 stage-0 条目。冲突条目、split/sparse/特殊标志等未显式支持的情况拒绝。
4. 经真实 index.lock 与哈希校验再发布。结果中的后续人工编辑留在工作区，不自动暂存；不提交、不移动 HEAD。

整轮 restore 仍沿用现有原始 index 恢复语义。未来如支持人工后续暂存，需为 index 单独设计选择性合并与审阅，不能顺带放开检查。

## 冲突、审阅与中断

规划先完成所选文件的全部检查。有冲突时，默认整个计划不应用；需要缩小范围必须创建新计划并重新审阅，不偷偷只应用成功文件。

冲突输出 S/E/C、候选冲突文本和原因，产物置于工作区外受控数据目录，不把冲突标记直接写入业务文件。支持用户编辑独立解决产物，再生成绑定其内容摘要的新计划；解决产物改变或业务文件变化都会使旧批准失效。文本合并无冲突也只是候选结果，仍需审阅和相关测试。

应用沿用现有资源恢复检查、会话/worktree 锁、备份、临时文件 fsync、替换前后哈希及 index.lock 规则。持久化计划、每文件 expected/desired 摘要、备份引用与 applying/partial/complete 进度。重启后只允许现场仍为该计划已知输入/输出状态的操作继续，且必须重新审阅；不能对混合现场重新计算一个新补丁并自动执行。未知锁与未知副作用继续拒绝。

外部编辑器不遵守锁，乐观检查与替换之间仍有竞争窗口，多文件应用不是事务；三方合并不会消除这个限制。

## 交付顺序与验收关口

每阶段都先完成必要验证，再开放下一阶段；不按未验证的工期承诺能力。

| 阶段 | 交付 | 开放条件 |
| --- | --- | --- |
| 1. 完整证据（已实现） | S/E 内容、index、执行关联、不可变封存、对象可达性和兼容版本；仅文件工具执行也建快照；提案区分 HEAD diff 与本轮 diff | 正常/取消/异常封存、后台排空、重复封存、崩溃、原始字节；旧版证据缺 E 内容时保持拒绝 |
| 2. 精确按文件撤销（已实现） | planner/review/apply 契约、选择性 index、统一安全写入与恢复 | 保留执行前人工修改和暂存，保留未选中文件，新增/删除正确；跨 worktree、旧令牌及人工 index 变化拒绝 |
| 3. 三方文本合并（已实现） | E 为祖先的规划器、后续不重叠编辑保留、冲突产物及显式解决流程 | 同处冲突不写业务文件；编码/换行、缺失路径及新增/删除冲突 |
| 4. 统一入口与恢复（已实现） | 本轮 proposal undo/undo_all 委托统一服务；CLI/API 同契约；部分失败与硬退出恢复 | 公开入口强制审阅；状态/锁/备份一致；真实子进程中断验收 |
| 5. 验收 | 迁移说明、限制文档、JUnit 结果证据 | 严格 restore 保持独立；后续设计不标记为已实现 |

内容对象复用 Git 对象库，直接保存原始字节；不再依赖 clean/smudge 重建工作区内容。计划、备份、冲突产物按 worktree 和本轮证据隔离；清理不得删除正在应用/部分失败的恢复引用。未应用冲突过期时可释放其 Git 引用，但保留独立冲突文件。存储失败拒绝撤销，不降级为无备份覆盖。不额外保存忽略文件或远程副作用。其他冲突产物只清理登记的固定文件，不递归删除目录中的未知人工文件。

## 操作入口

```text
research-agent checkpoint list --workspace <执行目录>
research-agent checkpoint undo-review --workspace <执行目录> --ref <本轮引用> --path <文件>
research-agent checkpoint undo-apply --workspace <执行目录> --review-token <令牌>
```

不传 --path 时选择本轮尚未撤销的全部变化。可以依次审阅、撤销多个文件，已完成范围不会重复撤销。应用前必须核对完整计划；大文本预览可能截断，二进制无文本预览。

有冲突时返回 before / agent-end / current / result 的工作区外产物目录。文本冲突可编辑 result，再执行 undo-review ... --resolved <文件> 获取新令牌；产物或业务内容再变化则旧批准失效。也可以用 undo-cancel --workspace ... --review-token <冲突令牌> 放弃冲突计划，业务文件保持不变。新增/删除、二进制等冲突不通过文本结果通道自动解决，需人工处理后重审。

CLI 提案交互对选定范围展示撤销结果，再确认应用。HTTP 使用 POST /api/chats/{chat_id}/undo/review、/apply、/cancel；请求携带 workspace_dir，review 可带 paths/resolved，apply/cancel 必须带 review_token。绑定会话自动定位实际 worktree，并校验当前快照的 chat_id。冲突和状态拒绝返回 409；HTTP 工作在线程中执行，与命令行共用宿主锁和服务。现有 Web 前端尚无完整的冲突编辑界面。

旧版无本轮完整 S/E 的 proposal 继续采用原有严格拒绝混写的路径，不伪造内容证据来启用三方合并。

## 验收矩阵

- 归因与作用域：执行前人工已暂存/未暂存/未跟踪；执行期间已知人工混写；仅文件工具执行；后一轮依赖前一轮改动时拒绝撤销旧轮；重复撤销明确返回已处理。
- 内容：人工后改不同位置可保留；同位置冲突；人工已手工撤销导致 C=S 时返回无需操作；新增后人工修改、删除后人工重建、重命名成组、目录占位。
- 格式：Unicode 路径、空格/换行路径、CRLF/LF、BOM、无末尾换行、大文件、二进制、过滤器变化；不能无损处理时拒绝。
- Git 状态：保留原有暂存边界和未跟踪属性；选中文件与未选中文件混合；后续人工暂存拒绝；HEAD 改变、跨 worktree、特殊 index、旧证据缺失拒绝。
- 竞争与恢复：审阅后编辑、解决产物再编辑、应用前后竞争、外来 index.lock、文件写入/日志/index 发布阶段硬退出、备份失败和磁盘不足；均保留可解释结果与人工恢复证据。
- 性质：无 Agent 变化时不修改文件；C=E 时选定范围结果等于 S；S=E 的路径保持 C；生成计划不修改工作区；冲突不应用；同一计划不能跨工作区使用；退出后的恢复不隐式批准新结果。

验收以临时真实 Git 仓库和真实子进程故障注入为主。合并算法测试验证保留内容与冲突边界；系统评测验证审阅、状态、事件和恢复证据，不能仅靠健康事件证明文件内容正确。

## 后续另行设计

任意历史轮次撤销需要识别后续 Agent 依赖，不把后来 Agent 的编辑默认当成人工编辑。按 hunk 撤销需要稳定的补丁选择标识；人工后续暂存需要独立 index 合并；远程副作用需要补偿契约。这些都不随文本三方合并自动获得。

快照与三方撤销阶段全量验收：**632 passed / 8 skipped / 9 个第三方弃用警告，300.07 秒**；线程异常按错误处理。该阶段增加 33 个实际测试用例，覆盖内容保留、暂存边界、快照轮换、特殊 index 拒绝、Git prune 后暂存对象可达，以及文件替换/index 发布后真实进程退出。验收证据保存于 artifacts/selective-undo-acceptance.xml。后续异步 Git 回收接入后全量为 **649 passed / 8 skipped**，详见[存储维护验收](STORAGE_POLICY.md)。

后台封存 outbox 与 Git 入队目标隔离补齐后，最新全量 **665 passed / 8 skipped**，证据为 artifacts/background-snapshot-outbox-acceptance.xml；单独真实 Docker **7 passed / 15.39 秒**，证据为 artifacts/background-snapshot-docker-acceptance.xml。

八个默认跳过包括七项真实 Docker 测试和一个原有 Windows 超时语义用例。矩阵中未覆盖的特殊文件系统破坏、所有 Git index 扩展及语义正确性不属于已验证保证。外部编辑器、归因、忽略文件和远程副作用边界持续保留。
